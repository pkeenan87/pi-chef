# AGENTS.md

Pi extension that routes coding work across providers to cut cost per successful task. See README.md for user-facing behavior. This file is for agents working on this repo.

## Commands

```bash
npm test            # vitest, no network
npm run typecheck   # src and tests
```

Both must be green before you call a change done. There is no lint script.

## Layout

- `src/extension.ts`: Pi entry point. Registers commands, the virtual "auto" model, providers, and web tools. Keeps one `Workflow` per cwd. Holds the `/build` session driver (`buildHost`), the only code that opens Pi sessions for tickets.
- `src/commands.ts`: the command table (name, description, `run`; `drive` for `/build`, which the host runs with a session driver).
- `src/orchestrator/`: `service.ts` is the `Workflow` facade. Each command lives in its own module (`planning`, `interview` (the `/plan` interview and spec), `ticket-plan`/`tickets` (ticket validation, files, group mapping), `prompts`, `build` (`/build`: `startBuild`, `nextChunk`, `finishChunk`, and `runBuild`, the loop, pure over a `BuildDriver`), `review` (`/review`: findings dialog and fixes in the current session), `advisor`, `reports`) as a function over `WorkflowContext` (`context.ts`). Phase rules are in `machine.ts`.
- `src/router/`: `virtual.ts` (the stateful `cost-opt/auto` router: `routeVirtual`, pure and tested with fakes), `classify.ts` (Decisions classifier plus keyword fallback), `policy.ts` (tier choice, escalation), `select.ts` (picks the model within a tier: cost per success with Thompson sampling), `stats.ts`.
- `src/providers/`: `auth.ts` (account-login, az, vercel status), `clients.ts` (chat and Decisions clients, usage parsing), `runtime.ts` (registers foundry, vercel, and local with Pi), `vercel.ts` (OIDC token via the Vercel CLI), `pi-chat.ts`.
- `src/cost/ledger.ts`: spend summaries and budget status. `src/cost/quota.ts`: subscription quota use per provider (ranking only). `src/config.ts`: YAML layering, validation, and pricing.
- `src/storage/store.ts`: task state, the event log, the ledger, metrics, and locks.
- `src/git/workspace.ts`: `GitWorkspace`, git over `execFile` for the main checkout (branches, merge-base, working-tree diff, `commitAll`). Nothing in the repo pushes or talks to a forge.
- `src/review/`: checks and static review (`review.ts`), and the advisory model pass of `/review` (`model-review.ts`).
- `src/tools/`: `web_search` (Anthropic subscription, Haiku), `web_fetch` (local, public-only), and the plan tools `plan_questions` / `plan_spec` / `plan_tickets` (`plan-questions.ts`, `plan-flow.ts`, `plan-review.ts` (the scrollable full-plan review used by `plan_tickets` and `/show-plan`); `readonly-bash.ts` is the planning bash allowlist).
- `src/sandbox.ts`: the deny rules (`assertCommandSafe`) and the `/build` bash block (`buildBashBlock`). `src/redact.ts`: secret redaction.

## Rules that are not obvious from the code

- **Account providers (OpenAI, Anthropic, xAI) use Pi account login by default.** A key stored in Pi (`/login` with a key) is used only when the user config sets `providers.<name>.apiKeyFallback: true`; a project config cannot set it (`restrictProject`). While a provider is on a key, prices come from `billing: api-key` rows (`setBillingResolver`, fed by `FileAuthProbe.billing`); with no such row the cost is unknown, never the subscription's $0. Never read `OPENAI_API_KEY`, `ANTHROPIC_API_KEY`, or `XAI_API_KEY`. Do not name a config field so it ends in a secret word (`apiKey`, `token`): `containsSecret` rejects it.
- **No secrets in config.** `assertNoSecrets` enforces this. Tokens (az, vercel, oauth) live in memory only. Never log them or write them to state, the ledger, or prompts.
- **Policy is deterministic; models only advise.** Plan approval stays required. Merge stays manual (`approvals.merge`); nothing pushes, opens a PR, or merges. A project config can never loosen the user's policy fields (`orgProviderAllowlist`, `proprietaryCode`, approvals, budgets).
- **Credential and location fields are user-config-only.** `baseUrl`, `endpoint`, `apiKeyEnv`, `audience`, `projectDir`, `envFile`, and `decisionsPath` from a project config are ignored with a warning (`config.warnings`, shown by `/status`), unless the user does not define that provider and the value is the built-in default. Remote endpoints must be https; only `local.baseUrl` may be http, and only for loopback.
- **Unknown cost is never treated as zero.** Record `actualUsd: null` and let the budget treat it as spend or a warning. Do money math in integer micro-USD (`toMicroUsd` and `fromMicroUsd`).
- **Spawn processes with `execFile` and argv arrays, never a shell.** Put `--` before user-derived refs. Every check and setup command must pass `assertCommandSafe` (the deny rules).
- **Writes to `.pi-workflows/` go through `atomicWrite`, `withLock`, or append-only files.** Never truncate `events.jsonl` or the ledger.
- **Never use a ctx or `pi` captured before a session replacement.** `/build` opens a new session per ticket (`newSession`); Pi then invalidates the old ctx and pi, and any use throws. Post-replacement work goes through the ctx passed to `withSession` (`replacementCtx` and `live` in `extension.ts`), and the workflow is re-resolved from it (`workflowFor`) on every call.
- **`/build` drives Pi sessions only from `extension.ts`.** `newSession`, `sendUserMessage`, and `waitForIdle` are called from the command ctx or the replacement ctx, never from lifecycle handlers. `build.ts` stays pure over `BuildDriver`. The chunk model is set through the `RESTORE_MODEL` slot, which `session_start` reads (`restoreModel`) before `withSession` runs; the driver waits on `RESTORE_DONE` and refuses to start a ticket on the wrong model. Tickets run in the main session, so there is no child process, worktree, or pool.
- **Phase changes go through `transition`, which checks `machine.ts`.** Commands return results through `guard` and do not throw to Pi.
- **Ticket `checks` are command lines, never prose.** `validateTickets` rejects a check the deny rules would refuse and one whose first word is not a command on `PATH` (`checkLineProblem`), and `TICKET_RULES` tells the planner so. Checks and setup run any other command. A check that still cannot run (`ran: false`) stops the ticket as failed without escalation and without a metric strike: a pricier model cannot fix a plan. Only model-attributable outcomes feed `bumpMetric`.
- **Ticket spend is ledgered from the main session, priced from config rows like every other call.** `observeUsage` (`budget.ts`) records each assistant message with ` · ticket <id>` in the reason while `state.build.currentTicket` is set; `finishChunk` sums those entries (`ticketSpend`). Unknown cost stays `null` and makes the ticket cost unknown, never zero. Failures before any model request are a known $0 (`knownZero`), never `emptyUsage()`.
- **A new plan version resets run state through `forNewPlan`.** Attempts restart and only the runs of tickets whose text is unchanged are kept, so a revised ticket is built again.
- **The chat trail is part of the product.** `ctx.progress` posts one-line events (`ui.notify` info) and `ctx.report` posts multi-line markdown blocks (`sendMessage` with customType `cost-report`); both stay in the transcript. `/build` reports each ticket (model, time, cost, checks, commit) and ends with a table; `/review` reports every stage with elapsed time (`src/orchestrator/format.ts`); keep that when changing them. Timings come from `ctx.now()`, never `Date.now()`, so tests stay deterministic.
- **The model review advises; it never gates.** `/review`'s `passed` comes from the checks and the static findings only. `modelReview` findings are stored and shown for a person (in the numbered findings dialog too); do not fold them into `findings` or `passed`. "Fix all" and "Fix…" send the findings to the current session with `ctx.startTurn` (`/review` never replaces the session, so the live ctx is fine); `/review` never commits, pushes, or moves the phase. Setup commands (`setup:`) run in the repo root before the checks.
- **The router classifies only the user's own text.** Pi turns the hidden `plan-interview-context` message into one more user message, so `lastUser` in `virtual.ts` skips any message starting with a `[PLAN ...]` marker (`PLAN_CONTEXT_MARKER`). Keep that marker on every `/plan` rules constant, and keep MECHANICAL/security keywords out of our own prompt constants (a test checks it). While `/plan` runs (`deps.planning`), the chat tier is at least `standard`.
- **Price every new model.** Add a row to `pricing` in `.pi-workflows/config.yaml`, or the selector ranks it last as `price_unknown`.
- **Quota shadow prices and the attempt overhead rank; they never bill.** `routing.attemptOverheadUsd` (added to every priced candidate's price before dividing by its success rate, so a $0 model's record still matters), `quota.models` weights, and the `quota.providers` caps (`src/cost/quota.ts`, `shadowCost`/`rankingCost` in `src/router/stats.ts`) only change scores. Never add any of them to `actualUsd`, `budgetStatus`, `budgetRemainingUsd`, the over-budget filter, or `expectedUsd`. Give a new subscription model a `quota.models` row as well as its $0 `pricing` row.
- **Commits are the user's.** `GitWorkspace` supplies the `pi-cost <pi-cost@localhost>` name or email only for the part git has no configured value for (config at any level, or `GIT_AUTHOR_*`/`GIT_COMMITTER_*`); it resolves this once per workspace. `commit.gpgsign=false` stays so a signing prompt cannot hang a commit.
- **Do not let a ticket publish.** While a ticket runs the `tool_call` hook blocks `git push` and branch switches (`buildBashBlock`), and `commitAll` runs with `core.hooksPath=/dev/null` and `--no-verify` so hooks a model wrote never run. The hook is defense in depth; no command of this extension pushes.
- **Tests use fakes for transports, clocks, rng, `az`, and `vercel`.** Never make a real network call. Put shared fixtures in `tests/helpers.ts`.

## Unverified against live services

The `/build` session loop has only been run against fakes. Unverified: `sendUserMessage` resolving when the run ends, the order of `waitForIdle` and `agent_settled`, calling `newSession` again from inside the replacement ctx's `withSession`, Esc while a command is awaiting, and `setModel` through the `session_start` slot (including that it finishes before `withSession` runs). Also unverified: the `message_end` usage fields, the `modelRegistry.complete` call shape, `web_search` over oauth, Foundry `decisionsPath` for Microsoft-Decision-1, and Vercel `!command` key resolution in Pi are also unverified. When you change these, say so in the PR. Do not claim they work without a live check.
